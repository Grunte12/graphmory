# I-MEM bibliography: memory and retrieval systems to compare

**Scope.** I reviewed all 90 entries in the local I-MEM bibliography and classified the ones that name or discuss memory, retrieval, or agent tools. The local paper notes and related-work files were used as indexes only. Public papers and project documentation below are the sources for the shortlist claims; no unpublished I-MEM prose is reproduced. “Installable” means a public implementation or package is documented, not that it was installed or evaluated here.

## Highest-fit comparison candidates

Fit columns: coding-agent focus, Curator/write governance, canonical Markdown, explicit graph, and lifecycle handling. “Partial” means the work supplies a related mechanism but not Graphmory’s full role. Shortlist evaluations were checked against the linked paper; Obsidian Memory for AI is repository-documentation evidence only. No installation was performed.

| Candidate and source | Fit: coding / Curator / canonical Markdown / explicit graph / lifecycle | Public implementation | Evaluation reported by the source |
|---|---|---|---|
| [PROJECTMEM](https://arxiv.org/abs/2606.12329) ([repository](https://github.com/riponcm/projectmem)) | **Yes / partial / partial / no / partial.** Coding-agent memory, append-only plain-text events, Markdown bridge, and a deterministic warning before repeating known failed actions; no knowledge graph or stale-note exclusion. | Paper documents `pip install projectmem`; public MIT repository. | Two-month usage self-study across 10 projects and 207 events, package tests, and compatibility checks. The authors explicitly do not claim causal productivity improvement. See the [primary paper evaluation](https://arxiv.org/html/2606.12329). This is a workflow study, not a head-to-head quality benchmark. |
| [Codebase-Memory](https://arxiv.org/abs/2603.27277) ([repository](https://github.com/DeusData/codebase-memory-mcp)) | **Yes / no / no / yes / no.** Persistent code knowledge graph exposed over MCP for coding-agent exploration; it indexes code, not durable user or project decisions. | Public MIT source and benchmark repository; installation was not tested. | Paper reports tests on 31 repositories: 83% answer quality versus 92% for file exploration, with about 10× fewer tokens and 2.1× fewer tool calls. ### Mechanism references, not installation candidates

- [MemTxn](https://arxiv.org/abs/2607.27834) is a close write-validation and conflict-resolution paper. The local bibliography points to LongMemEval-S, LoCoMo, and MemoryAgentBench FactConsolidation results, but its dedicated local paper note is missing and its full text was not rechecked for this inventory. Treat those evaluation details as unverified here; no public installable repository was located in the bibliography.
- [Slednev et al., “Deterministic Long-Term Memory for LLM Agents”](https://zenodo.org/records/21210732) is a close Markdown-source plus hybrid retrieval paper candidate. Its Zenodo record, code availability, maturity, and benchmark details were not independently checked for this note, so it is a follow-up reading target rather than a verified runnable baseline.

## Local source-collection gaps and interpretation boundary

- The bibliography has 90 entries. Its paper-note directory has 44 short source-map notes: 43 match a current bibliography key and one is an extra note for a removed citation. There are no paper PDFs or HTML files in the reviewed collection.
- Forty-seven bibliography entries have no matching dedicated paper note. Missing notes among the closest tools and governance work include PROJECTMEM, MemTxn, Zero-Mem, StateAuditor, TrustMem, Kumiho, TierMem, MIRIX, HDSO, LangMem, MemTools, Governed Shared Memory/MemClaw, and the two Obsidian repositories. The filesystem-substrate and air-gapped Markdown papers also lack matching notes.
- The A-MEM, Mem0, Zep, and Codebase-Memory notes are short summaries rather than copies of their papers. The five priority rows above use current primary papers or project docs for the described mechanism and evaluation. For the other rows, this note deliberately leaves exact benchmark outcomes and current installation status unresolved where the local source collection did not establish them.
- Hindsight is not an entry in this bibliography; its workflow fit is already covered separately in [Hindsight as a workflow reference](hindsight-workflow-reference-2026-09-29.md).

No competitor was installed, and no benchmark or model evaluation was run for this inventory. It makes no claim that Graphmory outperforms any cited system.
