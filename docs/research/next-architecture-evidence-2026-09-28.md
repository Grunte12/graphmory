# Research checkpoint: alternatives for evidence completeness

This is a bounded research note for the next architecture decision. I verified three primary sources online. Their results motivate experiments; none establishes performance on Graphmory's Markdown curator workflow. The current local diagnostic reports Graphmory complete evidence in 12/12 answerable cases at @10 and 10/12 at @3, but the run has the source-integrity and timing gaps described in [the progress review](../evaluation/progress-review-2026-09-28.md). Treat that as a clue about ranking depth, not an acceptance result.

## Three distinct directions

| Direction | What the primary source actually evaluated | Possible fit for Markdown memory | Cost and evidence limits |
|---|---|---|---|
| **Contextualize evidence units before indexing** — [Anthropic, Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval) | Anthropic reports experiments across code, fiction, arXiv papers, and science papers, with varied embedding/retrieval setups. Its headline comparison uses Gemini Text 004 and top-20 retrieval: failure rate (1 − Recall@20) moves from 5.7% to 3.7% with contextual embeddings, 2.9% with contextual embeddings plus contextual BM25, and 1.9% after reranking the top 150 to 20 with Cohere. | Add the containing note title, heading ancestry, aliases, and narrowly generated section context to each retrieval representation, while preserving the original Markdown path and excerpt as the only citation evidence. This directly tests whether isolated sections lose the identity and topic needed to rank near the top. | This is an Anthropic engineering report, not an independent Graphmory replication. The source does not give a full cost table or enough detail to establish transfer to small personal-memory corpora. Generated context adds index-time model/token cost and must be refreshed when source notes change; reranking adds query-time cost. Synthetic context must never count as cited evidence. |
| **Iterative query decomposition and retrieval** — [Trivedi et al., IRCoT, ACL 2023](https://aclanthology.org/2023.acl-long.557/) | IRCoT alternates reasoning steps with retrieval on HotpotQA, 2WikiMultihopQA, MuSiQue, and IIRC. The paper reports gains up to 21 points in retrieval and 15 points in answer quality over one-step baselines. The evaluated setting uses GPT-3 or Flan-T5 variants on multi-hop open-domain QA. | Use an initial question to find a seed fact, then form a bounded follow-up query from that evidence to retrieve the linked fact or note; retain source paths for every hop. It targets questions where the second search depends on the first result, rather than merely paraphrasing the original query. | Results are on Wikipedia-style multi-hop QA, not curated Markdown memory. Multiple sequential model/retrieval calls increase latency and token cost; generated intermediate steps can misdirect later searches. The paper does not show the same gains for ordinary one-hop recall or establish citation correctness in a curator. |
| **Hierarchical graph summaries with map-reduce evidence aggregation** — [Edge et al., GraphRAG, arXiv:2404.16130](https://arxiv.org/abs/2404.16130) | The paper builds an entity/relationship graph and hierarchical community summaries, then maps a query over community reports and reduces the partial responses. It evaluates two roughly million-token corpora (podcast transcripts and news) with 125 generated global-sensemaking questions per corpus. GPT-4 answers are compared by an LLM judge on comprehensiveness, diversity, empowerment, and directness; the paper reports advantages over conventional vector RAG on comprehensiveness and diversity. | Consider only for questions asking for themes, recurring patterns, or coverage across many notes. For specific facts, local graph traversal plus original-note excerpts is a more relevant shape than corpus-wide generated summaries. | The paper's task is global summarization, not complete retrieval of a small set of exact supporting notes. Questions and judgments are LLM-generated/judged, and abstractive summaries can omit provenance details. Indexing requires model extraction and summary generation; each query can invoke many map calls plus a reduce call, with corresponding token, latency, and refresh costs. The source gives no evidence that those costs are worthwhile for Graphmory's current scale. |

## Recommended next experiment: contextual evidence units

**Researcher's proposal, not an adopted implementation plan.** The user requires complete paginated retrieval for a Curator, without a top-three or top-ten ceiling. Improvement at @3 is diagnostic only and cannot by itself justify changing that workflow. Before accepting this proposal, architecture review must check whether titles, aliases and heading context already exist in Graphmory and whether contextualization addresses the observed answer-completeness failures. The experiment and stop bar below remain a candidate until that review, not an authorized benchmark protocol.

This is the best first test because the current diagnostic's visible gap is at @3 while the required notes are present by @10. Contextualization changes the representation used to retrieve evidence, rather than another small ranking-weight adjustment. This is an inference from Graphmory's diagnostic, not a claim that Anthropic's reported gains will transfer.

Run one preregistered, two-arm experiment: current Graphmory retrieval versus a separately built index whose chunks receive a concise contextual prefix from their source note and heading ancestry. Keep question text, corpus, retrieval model, top-k, Curator, source-read protocol, and host fixed. Cite and score only original Markdown passages; keep generated prefixes separate in the trace. Preserve the current 14-case batch as exposed development evidence and do not call it a holdout. For any promotion decision, use a newly frozen, source-disjoint holdout with hidden labels.

**Stop bar:** make exactly one treatment run and no parameter-tuning loop. On the exposed 12 answerable cases, require Complete Evidence@3 to improve from 10/12 to 12/12 while Complete Evidence@10 remains at 12/12; abstention behavior and source identity must not regress. Record contextualization input/output tokens, index build and refresh time, query wall time, original-read time, and total model/tool calls. If the evidence threshold fails, reject this architecture for now. If it passes, it only earns one confirmatory run on the new holdout; no superiority claim follows from the exposed set. The holdout must independently meet the predeclared supported-answer, citation-support, abstention, and cost/latency gates before promotion.

The paper evidence is not enough to set an honest absolute dollar or latency cap: the Anthropic report omits a complete cost table, IRCoT uses different models and tasks, and GraphRAG has a much larger corpus and global-query workload. Set the operational budget from measured Graphmory host/model costs before the confirmatory run; do not derive it from paper percentages.
