# Three-arm live development comparison: native Basic Memory, Graphmory, full-source prefetch

## Question and frozen design

Does sending all original Markdown notes in Graphmory's first wide recall page improve a Luna Curator/Sol Lead answer relative to normal Graphmory recall and native Basic Memory hybrid search? This is a **development diagnostic**, not an independent benchmark or a general superiority test. The [manifest](../../eval/reader-pilot/prefetch-three-arm-manifest-2026-09-28.json) was fixed before generation against baseline `779e907`; the [source-support rubric](../../eval/reader-pilot/prefetch-three-support-rubric-2026-09-28.md) was fixed before reading answers.

The three previously exposed LoCoMo histories are `conv-26:40`, `conv-47:8`, and `conv-50:18`, all category-1, prefetch-ready questions with two annotated evidence paths. The pinned corpus SHA-256 is `79fa87e90f04081343b8c8debecb80a9a6842b76a7aa537dc9fdf651ea698ff4`. Each case used the same original Markdown corpus across arms. The Basic Memory arm used its native `0.23.2` hybrid search and a real local `bge-small-en-v1.5` embedding index, built once per case before generation. The other arms used Graphmory `--auto`, either normal selective reads or opt-in `--prefetch-wide-originals`. All nine workflows used fresh `gpt-5.6-luna` Curator and `gpt-5.6-sol` Lead, low reasoning, maximum ten rounds, a 300,000-byte input cap, and the same structured citation rule. Trial order rotated by case as recorded in the manifest. Gold answers were withheld from the models.

The official LoCoMo QA function bodies were extracted unchanged from pinned source SHA-256 `8e3be5d57ff2ff9ec5cd05939592f468c5f3f1fd95d13e431932bdf6bf0fd6fd`; this is **not** a run of the upstream full CLI. Source, index, manifest, tool and host identities were validated before scoring. Replaying the scorer produced byte-identical summary, labels, predictions and raw-score files. The accounting test rejects missing, duplicate or reordered attempts. The [compact results](../../eval/reader-pilot/prefetch-three-arm-results-2026-09-28.json), [raw QA scores](../../eval/reader-pilot/prefetch-three-arm-raw-scores-2026-09-28.json), and [blinded source review](../../eval/reader-pilot/prefetch-three-arm-blind-review-2026-09-28.json) preserve the outcome without publishing raw host traces or full transcripts.

## Observations

All 3/3 native Basic Memory indexes completed: 19, 31 and 30 notes embedded, zero embedding errors, in 14.1, 14.2 and 15.5 seconds. Native ingestion normalized every indexed Markdown file; both original and indexed hashes were checked. Index-build time is separate from the following workflow latency. All 9/9 generation workflows completed without a retry.

| Arm | Completed | Mean raw QA F1 | Supported-complete by one blind reviewer | Median workflow seconds | Gross input tokens | Cached input tokens | Original note reads |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Basic Memory hybrid | 3/3 | 0.111 | 0/3 | 21.0 | 154,111 | 43,520 | 0 |
| Graphmory normal | 3/3 | 0 | 0/3; one unclear | 30.4 | 184,044 | 23,040 | 7 |
| Graphmory full-source prefetch | 3/3 | 0.200 | 2/3; one unclear | 17.9 | 194,584 | 43,520 | 80 |

“Original note reads” counts separate full-source reads. Basic Memory's native search returned substantial matched content, so zero separate reads does **not** mean its Curator saw zero evidence. Conversely, prefetch sent all 19, 31 or 30 complete originals at once; the search/tool payloads differ materially. Basic Memory's three empty final citation arrays pass path-identity validation vacuously, but do not establish provenance. Graphmory prefetch used 364,356 tool-output bytes in total versus 64,932 for normal Graphmory and 218,012 for Basic Memory. These are observed bytes, not monetary cost. Gross input is highest with prefetch even though its small-sample median latency is lower. Cache, order and subscription allocation prevent a reliable cost comparison.

Per case, prefetch read both annotated paths in all three. Normal Graphmory read one of two in the beach and pets questions, and both in the paperwork question. For the beach question the blind reviewer marked prefetch's “two times” complete with both citations, normal Graphmory incomplete, and Basic Memory unclear with no structured citations. For pets, prefetch and Basic Memory gave three dogs, but only prefetch provided structured source paths; normal Graphmory answered only “at least two.” For paperwork, all answers said one explicit instance. The pinned reference says two, yet the reviewer found that the flood conversation mentions insurance without explicitly mentioning **paperwork**. That label/source conflict leaves all three semantic completeness verdicts unclear. The beach passages also leave some ambiguity about whether dated mentions are distinct trips. Do not count these ambiguous cases as proof of model error or advantage.

The reviewer saw only shuffled answer IDs, lead answers, citations, question/reference and copied source notes, not the arm mapping, scores, traces or treatment names. One uncalibrated Luna review is exploratory; it is not independent human adjudication. The review packet was regenerated with generic path/protocol labels **before dispatch** after an initial packaging check found a treatment word in metadata. No model trial, rubric or scored answer was changed.

## Decision and next gate

Keep full-source prefetch **opt-in**. It looks useful on these two answerable multi-hop development questions, but sending entire histories increased input and tool bytes, and the sample contains one disputed reference. Native Basic Memory hybrid is now an actual reproduced comparator, not an assumed keyword-only proxy. This experiment does not meet the project's supported-complete, noninferiority, latency-tail, monetary-cost or superiority gates. Before promoting anything, use an independent history-level holdout with source-verified labels, include answerable and unanswerable cases, repeat runs to measure variance, and compare the same full workflow including ingestion where relevant. The next tool-side candidate should select enough complete evidence without indiscriminately sending a whole history.

## Reproduction and verification

The preparation, runner and summarizer are `scripts/prepare-prefetch-three-arm.mjs`, `scripts/run-prefetch-three-arm.py`, and `scripts/summarize-prefetch-three-arm.py`; `scripts/prepare-prefetch-blind-review.py` creates a treatment-blind review packet. The manifest pins source hashes and execution order. The experiment's raw local vaults, native indexes and Codex traces were kept outside the repository and removed after sanitized results and score replay. `npm run check` passed (309/309 tests plus configured gates); `git diff --check` passed. Read-only status on the user's Obsidian vault returned `SYNC_CONFIG_NOT_FOUND`, unchanged by this experiment. No production recall defaults changed.
