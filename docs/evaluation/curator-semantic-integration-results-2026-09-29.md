## Before implementation

The physical synthetic runner was executed with the semantic dependency
deliberately unavailable. Curator still returned a lexical response instead
of invoking semantic inference or reporting the missing dependency. The
runner failed its `expanded === true` assertion. This reproduces the ignored
option; it is not a successful retrieval or model-quality trial.

The failed six-slot ledger is preserved at
`/private/tmp/graphmory-curator-semantic-before-2026-09-29/report.json`.
Its first attempted page has no expansion marker and zero candidates. Later
slots were not run. The [failed ledger](experiments/curator-semantic-before-2026-09-29.json)
is also published so this failure is inspectable without the local directory.

Twelve full lexical responses were saved before runtime edits, covering
three queries with ordinary, continuation, byte-budget and adaptive options
on an 18-note physical synthetic vault. Baseline:
`/private/tmp/graphmory-curator-lexical-parity-2026-09-29/before.json`.

### Actual inference evidence

The first targeted unit run failed an injected-lane ordering assertion:
the supposed nonmatching query contained a hyphen-separated word also present
in every fixture body. Lexical ranking correctly contributed to fusion, so a
semantic-only order was an invalid expectation. The test fixture is being
corrected to assert zero lexical candidates before that expectation. No
runtime ranking, frozen real-inference query or benchmark label was changed
in response. The failed log is preserved at
`/private/tmp/graphmory-semantic-integration-targeted-2026-09-29.log`;
the corrected targeted rerun passed 25/25, with log at
`/private/tmp/graphmory-semantic-integration-targeted-passing-2026-09-29.log`.

The [published run ledger](experiments/curator-semantic-integration-2026-09-29.json)
records queries, code/source hashes, every page and resource measurements.
The physical vault is generated by
`scripts/eval-curator-semantic-integration.mjs`; no personal vault was copied.
Run it with a new output directory and a reusable local model cache:

```sh
node scripts/eval-curator-semantic-integration.mjs --out /tmp/new-semantic-run --model-cache /path/to/model-cache
```

For each frozen query, ordinary pages, 2,000-byte bundles and adaptive bundles
returned the same sequence of 18 eligible note paths exactly once. The first
query uses a paraphrase without matching lexical terms; this verifies actual
semantic candidate access, not answer relevance. Five scope/governance
controls remained excluded. Each cold CLI check emitted one 450-byte JSON
line with expansion/model/lane metadata and the correct three-note slice.

Descriptive cold-process CLI wall times were 263.5 and 238.7 ms, with cached
model files/vectors and warm filesystem state. The parent API process peaked
at 467,376 KiB RSS on this tiny corpus; child CLI peak RSS was not measured.
These are not comparative speed or memory gains. The first API traversal
includes model loading and initial fixture vector generation; subsequent
traversals reuse disk vectors. Larger corpora have different resource costs.

### Legacy benchmark regression

The unchanged exporter completed all 300 SciFact queries on all 5,183 source
notes. Both original-ID runfiles have SHA-256
`019287a0ad1b3bc2a1eb04e08779897d4663aa4df4979c4833aa92ee98f642b8`.
There are no rank changes or omitted queries. The unchanged BEIR 2.2.0 scorer
returned nDCG@10 **0.70797**, Recall@10 **0.84667**, MAP@10 **0.65845** and
MRR@10 **0.67078**, with all aggregate dictionaries exactly equal to baseline.
See the [parity and official-score artifact](experiments/curator-semantic-legacy-parity-2026-09-29.json).

This proves the shared-helper refactor preserves the standalone legacy API;
it does not assign these scores to the new Curator candidate fusion. Source
and watched implementation hashes were checked again before completion.

## Limits

The synthetic experiment measures candidate access and governance, not
supported-complete answers. Dense ranking of every eligible note is not proof
that every returned note is relevant. Pagination is complete relative to the
loaded eligible corpus; an explicit scan limit still prevents an exhaustive
vault claim. The option remains off by default and large-corpus memory/latency
costs remain unresolved. Matched Curator/Lead comparisons and independent
confirmation remain necessary for the active goal.
