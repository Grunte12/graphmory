## Deterministic acceptance

Use controlled Markdown fixtures to verify that existing superseded/stale targets and out-of-scope targets remain excluded from current graph traversal but appear in informational excluded-reference diagnostics, not broken-link issues. Actual missing wiki/relative Markdown and ambiguous references remain issues. Bound both reported exclusions and issues without discarding total counts. Confirm current recall continues excluding superseded notes.

No vault writes are performed by graph audit. Information about excluded targets refers only to the supplied/scanned document inventory, not proof of filesystem-wide absence or semantic validity.

## Installed native acceptance

One freshly packed/installed isolated package, Codex CLI recorded version, one Lead `gpt-5.6-sol` low and one actual named `graphmory_curator` child `gpt-5.6-luna` low, dispatched with `fork_turns=none`. Two sequential tasks using the existing synthetic Helios approved-supersession fixture:

1. Validate the lead-authored patch before any write, read the original E1/E2 source and affected notes through `read-notes`, apply the explicitly authorized E2 update, retain the prior policy/E1, mark it superseded and link it forward, and preserve the successor's explicit backward history link. Run the lifecycle persistence postcheck plus graph/lifecycle audits. Return `APPLIED` only with evidence and post-state checks. Do not use proposal-only `curate-plan` in default Curator mode.
2. After task 1 completes, the parent records a full Markdown SHA-256 snapshot outside the vault, then delegates the exact patch once. Require no duplicate and all final Markdown bytes equal that snapshot. Ask the child to recall the current rule without historical inclusion and the predecessor explicitly with `--include-superseded`, citing source paths. Historical visibility is not proof that the predecessor remains current authority.

Actual parent/child traces must verify named role/model binding, preflight-before-write, successful source reads, postcheck before completion, snapshot-before-retry ordering and both terminal tasks. No generic/inline fallback, hidden retries or prompt variants. Stop and preserve failures if dispatch or tool execution fails. The declared patch replay is an idempotency check, not retrying a failed model attempt.

Root independently runs the installed lifecycle postcheck and graph audit and checks full evidence hashes, both history directions, active/superseded statuses, Runbook's current link, retry hash equality and current-versus-historical recall. Record malformed/read errors and remaining audit findings, including informational exclusions, separately. A clean audit alone cannot pass lineage acceptance.

This is a development acceptance on an already inspected synthetic case, not a new holdout, official benchmark or comparative latency/cost result. The default-path command/guidance and graph-classification changes are a bundle; a successful run does not isolate their individual contribution. No private vault mutation, official-score change or comparator run. Archive only exact terminal native sessions and remove the reviewed temporary root after metadata-only JSON/Markdown evidence capture.
