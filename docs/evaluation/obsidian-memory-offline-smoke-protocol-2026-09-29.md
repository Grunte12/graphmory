## Commands and gates

Run from the copied `vault-v41/` with `PATH="$PWD/.venv/bin:$PATH"` exported; set `MEMORY_TODAY=2026-09-21` for date-sensitive checks. `TXN_ID` and `PROPOSAL_ID` are parsed from the CLI’s JSON `data` field. Capture stdout/stderr only long enough to hash them; persist result metadata and hashes, not raw outputs or vault content. The reference fixture's `agent-human-00000001` is a synthetic role-policy identity, not a real human approval or judgment.

1. **Prepare the isolated fixture:** copy the pinned v4.1 example vault to `vault-v41/`; run `git init`, configure a synthetic local identity, commit the untouched example as baseline, then run `python3 -m venv .venv` and `.venv/bin/pip install -r requirements.txt`.
2. **Shipped checks:** run `.venv/bin/python tools/lint.py --strict`; `PATH="$PWD/.venv/bin:$PATH" MEMORY_TODAY=2026-09-21 tools/rebuild-views.sh`; `PATH="$PWD/.venv/bin:$PATH" MEMORY_TODAY=2026-09-21 tools/rebuild-indexes.sh`; and `PATH="$PWD/.venv/bin:$PATH" tools/query.sh facts --entity elena-voss --json`. Gate: each exits 0 and query returns the fixture’s existing facts. No benchmark score is inferred.
3. **Approved proposal, authorization refusal, and retry:** run `.venv/bin/python tools/propose.py --json create --title "Offline smoke approved update" --namespace facts --proposer agent-local-1234abcd --op create_fact --entity elena-voss --predicate tool --value offline-smoke-approved`; first run `.venv/bin/python tools/review.py approve --proposal-id "$PROPOSAL_ID" --reviewer agent-test-1234abcd` and require nonzero exit; then approve with `agent-human-00000001` and run `.venv/bin/python tools/propose.py apply --proposal-id "$PROPOSAL_ID" --yes`. Gate: unauthorized review is refused, authorized review/apply succeeds, and the new fact file exists. Record target-file count/hash and matching apply-journal count. Re-run apply and re-record; gate: exit 0 with idempotent-skip outcome and those counts/hashes unchanged. Then rerun strict lint and the fact query; require exit 0.
4. **Transaction retry:** capture baseline `git rev-parse HEAD`; run `.venv/bin/python tools/transact.py --json begin --idempotency-key obsidian-smoke-retry-2026-09-29 --agent agent-local-1234abcd --expected-revision "$BASELINE"`; parse `TXN_ID`; run `.venv/bin/python tools/transact.py add --txn-id "$TXN_ID" --op create_fact --entity elena-voss --predicate collaborator --value offline-smoke-retry`; then `.venv/bin/python tools/transact.py commit --txn-id "$TXN_ID" --yes`. Record the target-file count/hash and matching journal count. Begin again with the same key, agent, and baseline; re-record both measurements. Gate: all commands exit 0, retry returns the committed transaction ID/idempotent-skip, and target-file count, target hash, and one matching journal count remain unchanged.
5. **Stale-review refusal:** create a second proposal for `concordance/language` with value `offline-smoke-stale`, approve it as `agent-human-00000001`, then change only its title in the copied proposal Markdown while preserving the original `content_hash` and review. Apply must exit nonzero with content-hash/stale-review diagnostics, and `memory/facts/concordance/language.md` must remain absent. This intentionally leaves the disposable copy’s proposal invalid; do not use a subsequent full-vault lint as a pass/fail gate.

Stop after these gates. Do not run the upstream full suite, model sessions, retrieval-quality scoring, source-support judgments, or a Graphmory head-to-head. A stale Git revision refusal is not Graphmory’s semantic memory-conflict case; a missing/dangling evidence link is not semantic evidence support.
