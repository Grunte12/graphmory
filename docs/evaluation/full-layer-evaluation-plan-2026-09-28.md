# Full-layer evaluation plan — 2026-09-28

## Decision and evidence boundary

Graphmory has useful regression coverage across its memory pipeline, but no measured official full-benchmark answer result. The next priority is a small traceable reader evaluation that separates missing evidence, delivery loss, curator distortion, and answer errors. Do not add a new retrieval architecture before establishing which stage fails.

This is a planning and source audit, not an experiment. It inspected selected public repository modules, test definitions, and existing reports; it did not inspect private vaults or unopened holdout contents, install dependencies, call a paid model, or rerun benchmarks. Baseline reported by the completed scorer repair is HEAD `fd84bd5`, 274/274 regression tests and configured deterministic gates passing; see [repair evidence](scorer-correctness-repair-2026-09-28.md). Those counts describe the reported baseline, not a new run in this plan.

The installed [eval-audit](../../.agents/skills/eval-audit/SKILL.md), [evaluate-rag](../../.agents/skills/evaluate-rag/SKILL.md), and [validate-evaluator](../../.agents/skills/validate-evaluator/SKILL.md) guided the inspection. Their sample sizes, suggested k, judge thresholds, and automatic correction advice are heuristics, not universal acceptance criteria. Preserve official benchmark metrics even where overlap is weak; add stricter diagnostics alongside them. No claim here covers all research or every possible failure.

Every result must carry one of these evidence classes:

| Class | Meaning |
|---|---|
| `regression` | Deterministic implementation or scorer invariant on controlled inputs. |
| `synthetic` | Fabricated/public fixture task, including live model outputs on that task. Repetitions are not new tasks. |
| `custom_dev_diagnostic` | Development subset, adapted corpus, custom metric, private sanity-check aggregate, or inspected acceptance data reused for tuning. |
| `official_full` | Pinned official complete split/protocol/scorer with documented exclusions; adaptations disclosed. No existing answer result in this audit qualifies. |
| `unmeasured` | No applicable evidence; numerical value is null, never zero. |

A diagnostic computed with an official scorer on a selected subset remains a development diagnostic. Regression success cannot establish semantic correctness or production generalization.

## Prioritized findings

1. **P1 — Answer validity is the immediate bottleneck.** The [Astra audit](astra-eval-skill-audit-2026-09-28.md) reproduced 1,099 LoCoMo development cases per arm (2,198 case/arm rows), but these are custom session retrieval measurements. Official QA remains unmeasured. The eight-question live synthetic preview study has 32 rows across arms/repeats: 32/32 required-fact/path checks but only 25/32 strict supported answers, with author/manual unblinded grading. Correct facts plus citations can still invent a relationship or constraint.
2. **P1 — Evidence completeness and delivery need joint traces.** Fusion category-1 complete@5 is 53/180; multi-session complete@5 is 65/209, despite mean distinct-session recall@5 of 85.72%. These are custom development diagnostics. Full-ranked-list reachability is 1,099/1,099 but does not prove that a reader saw adequate excerpts, paged far enough, or answered correctly. Per-page budgets must not become an assumed universal total top-k cap. Adaptive candidate/round budgets remain explicit policy limits and require distinct stop reasons.
3. **P1 — Write evaluation must preserve the repaired validity gate.** Protocol `write-decision-v2-complete-denominator` repairs wrong-action compensation and missing/duplicate coverage. Historical synthetic pilot regrades are A 8/11, B 7/11, C 7/11; they do not validate semantic entailment. `runComplete: false` invalidates any apparent high pass rate. Metadata completeness and exact provenance IDs cannot prove a claim is supported.
4. **P2 — Semantic judge reliability is unknown.** No independently adjudicated held-out confusion matrix was established. Obtain human labels before presenting a judge's strict-support verdicts as calibrated accuracy. Existing automated or author grading must retain its provenance.
5. **P2 — Lifecycle and tool mechanics have stronger evidence than autonomous behavior.** Synthetic state checks can establish that known unsafe transitions are blocked; they do not show a live agent recognizes semantic contradictions or chooses the correct scope, tool, source, and stopping point.
6. **P2 — Efficiency evidence is local and conditional.** Host counters, output bytes, warm-process speedups and one-host pilots are useful diagnostics. They are not billed savings, cache-hit guarantees, latency tails, or matched end-to-end superiority. The [usage pilot](host-usage-pilot-2026-09-27.md) explicitly records these limits.

## Metric dictionary

Use a fixed expected-case manifest. Let N be eligible expected cases after predeclared exclusions, G the required evidence units/groups for a case, R_k its top k unique retrieved units, D the evidence actually delivered, and C the material claims asserted by the answer. Record units explicitly (session, note, section, turn, fact); changing units changes the metric. Empty denominators are undefined/null with a reason.

| Metric | Purpose and definition | Limit |
|---|---|---|
| Run coverage/validity | `unique valid expected outputs / N`; separately count missing, duplicate, unknown, malformed, timeout and tool/model errors. Validity requires the predefined protocol and exact expected coverage. | A per-row pass fraction never overrides invalid run status. Preserve errors in operational-success denominator. |
| Action/state success | `cases satisfying correct permitted action AND required post-state AND all critical safety checks / N`. | A synthetic exact oracle covers only its modeled states. Semantic equivalence may require human review; metadata points cannot compensate wrong actions. |
| Schema validity | `valid contracts / expected contracts`. | Structure only; no entailment or usefulness claim. |
| Retained write facts | `supported required durable facts preserved / required durable facts`; separately `unsupported saved claims / saved claims`. | Requires reviewed claim segmentation and significance labels. Deleting all claims must not appear successful. |
| Link integrity | Resolved intended references / references expected to resolve; ambiguous/unresolved counts separate. Derived freshness = matching current source hashes / indexed sources. | Resolved endpoints do not prove the relationship is true; scope of reference parser matters. |
| Recall@k / hit@k | `|G ∩ R_k|/|G|`; hit is `1[intersection nonempty]`. Macro-average per question. Group alternatives count a group once if any accepted member is found. | Annotated evidence may be incomplete. Distinct-session recall differs from evidence-turn weighted recall. Hit can conceal missing hops. |
| Complete evidence@k | `1[every required group has a retrieved member]`, averaged over cases. Complete-delivered uses D and verified supporting spans instead. | Candidate path presence need not mean sufficient text. k=3/5/10/20 are diagnostic checkpoints, not total note limits. |
| Precision@k | Relevant returned units / k, with the short-list denominator convention fixed in advance. | Precision against incomplete qrels undercounts valid alternatives; short-list conventions must not silently change. |
| MRR | Mean `1 / rank(first relevant unit)`; zero if missing. | First-hop/single-fact priority only; does not measure full multi-hop support. |
| nDCG@k | `DCG/IDCG`, using a frozen gain convention, e.g. `sum((2^rel_i−1)/log2(i+1))`. Report qrel scale and evaluator implementation. | Different gain conventions differ for graded labels. No relevant gold means undefined unless official protocol specifies otherwise. |
| Pagination/delivery success | Complete-delivered cases / eligible cases; premature stop = incomplete support with available continuation / cases requiring continuation. Also pages, reads, duplicated bytes, error counts and stop reasons. | A budget-exhausted case is not successful abstention by definition. Full text delivery may increase distractors. |
| Tool-call correctness | Expected tool/action/argument predicate and state transition satisfied / expected opportunities. Critical forbidden calls counted separately. | Multiple valid sequences require equivalence rules; exact order only when dependency requires it. Fewer calls alone is not better. |
| Brief retention and added claims | Required evidence facts preserved in brief / required facts; unsupported material brief claims / all material brief claims. Compression = brief tokens / source tokens with tokenizer pinned. | Semantic labels needed. Compression savings with omitted constraints are not a success. |
| Official answer score | Run the pinned benchmark's unmodified scorer and report categories, split, scorer/model and denominator. | Token overlap or permissive judge matches do not guarantee all claims supported. An adapted subset is not an official full result. |
| Strict supported answer | Binary: every material asserted claim follows from actually delivered evidence with correct relation, scope, negation and time; abstention contains no invented answer. | Support alone allows incomplete answers, so pair with required-answer completeness. World knowledge or a correct guess without delivered support fails this criterion. |
| Supported-complete success | Strict support AND all required answer elements correct/present (or correct justified abstention) AND protocol valid. Divide by N. | Gold omissions/ambiguous alternatives require adjudication; preserve raw official scores alongside this stricter secondary result. |
| Citation precision/recall | Precision: supporting citations / assessed citations; recall: claims requiring attribution adequately supported by attached citations / such claims. Document whether multiple citations jointly entail a claim. | Identifier presence is not entailment. Adapted ALCE-style definitions with another judge are not official ALCE scores. |
| Currentness/contradiction | Correct current state / temporal answerable cases; contradictory or stale assertions / relevant cases. Include answers containing both new and obsolete facts as failures when mutually inconsistent. | Needs query date and lifecycle truth; a latest-answer keyword can pass despite a stale added claim. |
| Abstention sensitivity/specificity | Correct abstentions / unanswerable cases; correct answers (without inappropriate refusal) / answerable cases. Also false-answer and false-refusal counts. | Retrieval candidates on an unanswerable question prove neither hallucination nor good abstention. Phrase-only refusal checks are weak. |
| Repeat reliability | Fraction of tasks succeeding in all k prescribed attempts; where benchmark requires it use its exact pass^k estimator. | This is not pass@k (at least one success). Report k, task clusters and trial correlation; do not exponentiate a pooled rate blindly. |
| Attack resistance | Clean utility, utility under attack, and successful attacker objectives / valid attack trials, with failed/invalid attacks separately recorded. | A malicious-note fixture suite adapted from AgentDojo is not the official suite or comprehensive security assurance. |
| Latency | Median and p95 end-to-end wall time; local retrieval, source read, model calls and retries separately. | Tiny pilots do not estimate tails reliably; disclose N, hardware/load and timeouts. Parallel stages do not sum to wall time. |
| Tokens and cost | Per-provider uncached input, cache reads, cache writes, output and other billed units. Known cost sums each unit × dated price plus fees/storage; cost per success = all eligible trial costs / supported-complete successes. | Avoid double counting provider totals. Unknown fields/billing null; zero successes makes cost per success undefined. Subscription allocation requires an explicit separate method. |
| Judge validity | TPR = judge pass / human pass cases; TNR = judge fail / human fail cases, plus full confusion counts, false passes and category-specific uncertainty. | Independent labels and held-out validation needed. One absent class means its rate null. Drift invalidates transfer assumptions. |

Rogan–Gladen correction `(observed_pass + TNR − 1)/(TPR + TNR − 1)` is optional only under defensible stable error rates and population assumptions. Report uncertainty in both calibration and evaluation samples; do not hide an unstable denominator with clipping. It is not a substitute for real labels or a default correction across changed domains.

## Benchmark selection and adaptation boundaries

**Run next: LoCoMo and LongMemEval reader development checks.** They align with multi-session memory and already have local adapters. The [pinned LoCoMo evaluator](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/task_eval/evaluation.py) uses category-specific answer metrics: multi-answer F1 for category 1, stemmed answer F1 for categories 2–4, and a weak phrase-based abstention check for category 5. Preserve it; supplement with strict support and abstention review. Local retrieval excludes 330 category-5, six unresolved-gold and four empty-evidence cases from 1,439 development questions: these exclusions must not silently carry into answer evaluation. Source hash and seven-conversation development split are documented in the audit. Leave the three unopened conversations sealed until the reader protocol is frozen.

[LongMemEval](https://github.com/xiaowu0162/LongMemEval) offers cleaned S/M/oracle variants and a category-aware answer judge; pin exact data, evaluator code and judge snapshot before execution. Its documented default QA judge is `gpt-4o-2024-08-06`; substituting another judge is a disclosed protocol change. Keep official retrieval recall_any/recall_all/nDCG reporting separate from local grouped-session diagnostics, and record the official retrieval treatment of abstention cases. Local 58-answerable/10-abstention development data is diagnostic; already inspected acceptance aggregates are no longer fresh evidence for subsequent tuning. Preserve original history for the standard track; strict-time trimming is a separate adaptation. Add contradiction checks when a judge can accept the latest answer despite a stale conflicting addition.

**Conditional next: one external multi-hop transfer check.** [HotpotQA](https://github.com/hotpotqa/hotpot) provides answer EM/F1, supporting-fact EM/F1 and joint scores. [MuSiQue](https://github.com/StonyBrookNLP/musique) provides composed 2–4-hop questions, answer/support F1, and sufficiency evaluation for its full setup. Choose one after observing a persistent hop failure; preserve official version, split, evidence granularity and leakage filters. Mapping paragraphs to Markdown or graph edges is an adaptation and must not insert gold reasoning links unavailable to the tested system. These tasks test transfer from encyclopedic evidence, not memory updates or coding-agent usefulness.

**Optional, scoped references; do not run them all now.** [BEIR](https://github.com/beir-cellar/beir) supplies standard qrel ranking evaluation and public transfer corpora, useful if retrieval generalization becomes the question; it does not validate product memory. [BFCL memory](https://gorilla.cs.berkeley.edu/blogs/16_bfcl_v4_memory.html) motivates memory-operation/state checks; an adapted Graphmory CLI task is not an official BFCL result, and its memory backends are not equivalent to a Markdown vault. [τ-bench tooling](https://github.com/sierra-research/tau2-bench) motivates end-state and repeated all-trial reliability; freeze τ versus τ² version explicitly rather than combining them, and disclose simulated users/domains. [ALCE](https://github.com/princeton-nlp/ALCE) motivates citation entailment precision/recall; its official evaluation uses its configured NLI machinery, so a cheaper substituted judge must receive a custom label. [AgentDojo](https://github.com/ethz-spylab/agentdojo) motivates separating utility from attack success; malicious vault-note adaptations are a custom suite. [MemoryAgentBench](https://arxiv.org/abs/2507.05257) is a possible later retrieval/learning/long-range/conflict transfer check, not an existing result.

A development evaluator library is optional. For example, [DeepEval at the reviewed revision](https://github.com/confident-ai/deepeval/tree/385117c9c46e6935866422b7aa1f67e5e2824472) separates deterministic list/order checks in ToolCorrectness from LLM-dependent options and metrics. Do not describe all tool correctness as deterministic: available-tool analysis, argument/task/plan judgments can invoke a model. ToolCorrectness can initialize a model even when its core comparison is deterministic; inspect initialization and credential requirements before choosing an execution path. No evaluator package is required for end users or needed to complete the minimal next run.

## Frozen experiment controls and attribution

Before generation, save a manifest with repository commit and dirty diff hash; every implementation/scorer file hash; dataset source URL/revision/SHA-256; case IDs and per-case content hashes; split assignment and grouping key; source vault/rendering hashes; expected outcomes and exclusions; prompts, adapters, tools and host configuration hashes; model/provider dated IDs, decoding settings, seed when supported, output limits and timeouts. A seed does not guarantee hosted determinism. Mutable upstream `main` links in this plan are discovery references, not execution pins.

Keep gold answers, relevance labels, benchmark summaries and evaluator files outside the reader's allowed filesystem and inputs. Validate isolation independently of field stripping. Record shared history/family dependencies before splitting; split by conversation or source family to reduce leakage. Never promote cases consulted during design to fresh holdout. Public dataset pretraining contamination remains possible.

Freeze corpus preparation, query/date, eligible lifecycle/scope filters, section rendering, context budget and continuation policy across paired retrieval arms. Add Thai-query-to-English-note bridging as an explicitly labeled diagnostic slice when testing the actual language workflow; preserve canonical English notes and do not introduce translated duplicate memory. Log actual pages, offsets, candidate ranks, full-source reads/hashes, delivered bytes/tokens, truncation, model/tool calls and final stop reason. Continue while needed and allowed; record exhausted round/candidate/token budget explicitly. Record every expected row, including absence/error/refusal, before scoring. Keep protocol failure, quality failure and infrastructure failure distinct while including all in operational success; provide a successful-execution-only quality view as a secondary conditional metric.

Use matched reader/model/prompt for these smallest attribution arms:

| Controlled comparison | Isolates | Interpretation caveat |
|---|---|---|
| No memory vs oracle evidence vs predicted evidence | Memory benefit and retriever opportunity gap | Oracle is a diagnostic upper condition, not a deployable system or mathematical upper bound for a fallible reader. |
| Same retrieved source IDs, full sources vs previews plus paging vs curator brief | Delivery and compression loss | Match available evidence and record different token amounts; also run a budget-matched view when needed. |
| Same candidate pool, rerank off/on | Ordering benefit | Do not simultaneously change corpus, curation or reader. |
| Same retrieval and delivered evidence, reader/curator prompt change | Reader/curator behavior | Requires paired fresh sessions; development tuning invalidates a final-test interpretation. |
| Same original task, current memory vs deliberately stale/conflicting memory | Lifecycle selection and temporal reasoning | Artificial corruption remains synthetic; preserve immutable source evidence. |

Randomize/counterbalance paired arm order by task and repeat, record the seed and actual order, use isolated sessions, and retain all retries. Keep intentional warm/cold process and provider-cache conditions separate. Fresh host sessions do not guarantee a cold provider cache. Hold hardware/OS/Node/host versions, process concurrency, machine load, corpus size, file lengths and optional model hardware constant or record their changes. Do not run latency acceptance alongside tests.

Capture provider-native usage and host-normalized fields with their mapping. Cache eligibility, prefix matching, writes, TTL and storage vary by provider; consult the frozen dated versions of [OpenAI](https://developers.openai.com/api/docs/guides/prompt-caching), [Claude](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), and [Gemini](https://ai.google.dev/gemini-api/docs/caching) documentation for the chosen run. Preserve unknowns. Do not equate bytes with tokens, prompt-cache compatibility with savings, or host `cost: 0` with zero billed cost.

Report paired per-task deltas and bootstrap or suitable interval estimates grouped by independent conversation/family/task, preserving paired arms and repeats inside each group. LoCoMo development has seven conversation clusters, not 1,099 independent conversations; uncertainty is correspondingly limited. Disclose interval method, number of groups, sample selection, repeats and failure denominator. Do not claim significance from treating 32 synthetic rows as 32 independent questions.

## Cheapest-first execution stages and gates

1. **Freeze existing evidence and deterministic validity.** Reuse repaired scorer tests and dataset/runner isolation checks; validate registry paths and manifest completeness. Gate: no unexplained missing/duplicate IDs, wrong-action false passes, source mutation, gold access or version mismatch. Preserve historical scores by scorer version. These are correctness invariants, not a proposed universal accuracy target.
2. **Small development trace pilot.** Predeclare representative random questions plus the observed multi-hop/scope failures and answerable/unanswerable temporal cases; label purposeful sampling. Use the minimal no-memory/oracle/predicted arms, adding source-versus-brief only where attribution requires it. Gate: every expected trial accounted for, evidence and tool trace reconstructable, and failure location assessable. Infrastructure failures must be fixed before any architecture claim.
3. **Human adjudication and targeted repair.** A knowledgeable reviewer, blinded to arm where feasible, labels support, completeness, scope/negation/currentness and abstention on failed plus randomly sampled passing traces. Resolve ambiguity with cited evidence; preserve reviewer provenance. If an LLM judge is introduced, disjoint development and test labels must measure its false-pass/false-fail behavior with uncertainty. Gate: no unvalidated semantic judge presented as calibrated correctness; uncertain categories remain manually reviewed or unmeasured.
4. **One controlled intervention and paired development check.** Choose the demonstrated bottleneck: rank/coverage, paging/source delivery, curator retention, or reader instruction. Predeclare primary metric, safety invariants, acceptable quality noninferiority margin and practical cost/latency improvement based on product risk and baseline variability. Exact margins/sample sizes remain to be fixed before the run; this plan does not invent them. Gate: the chosen margin/interval decision is met, critical failure patterns do not regress, and unknown cost prevents a savings claim.
5. **Frozen final evaluation.** Only after preceding gates and authorization for any model expenditure, evaluate the unopened LoCoMo holdout once and obtain fresh LongMemEval evaluation cases suitable for the claim. Run full official splits only when seeking full benchmark comparisons and state model/protocol deviations. Gate: use the predeclared decision rule, retain all failures/exclusions, and label each claim at its actual evidence level. A custom holdout subset does not become `official_full` merely because it was sealed.
6. **Expand only for uncovered product risks.** Add multi-hop transfer, live write/lifecycle sequences, host matrix or adversarial-note checks when a concrete claim requires them. Keep full-product claims separate from retrieval-adapter pilots. No giant combined score is required.

The minimal next deliverable is one frozen reader pilot manifest and a reviewable trace table containing question, delivered evidence/tool sequence, answer, official score where applicable, strict-support/completeness/abstention verdicts, cited rationale, usage and error status. It closes the largest evidence gap before more benchmark breadth or retrieval complexity.
