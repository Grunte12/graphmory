# สรุป Graphmory MVP — 1 ตุลาคม 2026

## สถานะ

**พร้อมทดลองใช้ตามขอบเขตที่ทดสอบแล้ว:** Codex CLI 0.146.0 + Lead และ Curator `gpt-5.6-luna` ระดับ low + Node 24.18.0 + vault Markdown ในเครื่อง

เกณฑ์ G1–G9 ผ่านครบ หลังเก็บผลรอบที่ส่งงานผิดและแก้การส่งงานอีกหนึ่งรอบ ส่วนโมเดลเริ่มต้น `gpt-6-luna`, Cursor, Claude และ vault หลักของผู้ใช้ยังต้องมีการทดลองใช้งานของตัวเอง

## สิ่งที่ทำเสร็จ

| ส่วน | สิ่งที่เพิ่มหรือแก้ | ประโยชน์ |
|---|---|---|
| บันทึกความจำ | สร้างโน้ตจาก patch และตรวจครบทั้งข้อสรุป ขอบเขต แหล่งที่มา และ lifecycle | ตรวจพบข้อมูลสำคัญที่หล่นหาย แทนการตรวจแค่ metadata |
| Lifecycle | กฎวันหมดอายุชุดเดียวกันใน retrieval และ audit | ข้อมูลหมดอายุไม่ถูกใช้เป็นข้อเท็จจริงปัจจุบัน แม้แคชเคยอุ่นแล้ว |
| งานเขียน | เก็บ checkpoint และสำเนาก่อนแก้ไว้ภายนอก vault | รู้ว่างานใดค้างอยู่ และหยุดการใช้ความจำที่ยังแก้ไม่เสร็จ |
| กู้คืน | ตรวจ hash ปัจจุบันก่อนคืนไฟล์ พร้อมขั้นตอนอนุมัติสำหรับ lock จากโปรเซสที่หยุดแล้ว | กู้คืนงานที่ถูกปิดกลางทางได้ และเก็บไฟล์ต้นทางที่ถูกแก้จากภายนอกไว้ |
| Curator | คู่มือและ role ใช้งานผ่าน CLI ที่ติดตั้งจริง | Lead ส่งงานครบชุดให้ Curator แล้วรับผลสรุปกับ receipt กลับมา |
| การส่งมอบ | แพ็กเกจมีคู่มือ รายงาน และลิงก์ที่ใช้ได้ | ทดลองติดตั้งได้โดยไม่ต้องใช้ API เพิ่มหรือดาวน์โหลดโมเดลในเครื่อง |

## ทดสอบอย่างไร

ใช้ **vault จำลองที่มีไฟล์ Markdown จริง** พร้อมไฟล์ `.obsidian` และเปรียบเทียบ hash ทุกไฟล์ก่อน–หลัง ไม่ได้แก้ vault หลักของผู้ใช้ และไม่ได้เปิดแอป Obsidian เพื่อทดสอบนี้

- `npm run check` ผ่าน **394/394 เทสต์** รวม examples และ eval ที่กำหนดไว้
- Curator ต้องค้นหาต่อไปยังหน้าสอง อ่านหลักฐานต้นฉบับ และใช้ graph engine เดินผ่านลิงก์จริง
- การอัปเดตนโยบายแก้เพียง **3 ไฟล์ที่อนุญาต** พร้อมเก็บนโยบายเก่าและลิงก์ประวัติทั้งสองทิศทาง
- กรณีหลักฐานไม่พอและหลักฐานขัดกันไม่แก้ไฟล์เลย
- เซสชันใหม่อ่านความจำปัจจุบัน ประวัติ และ preference ได้ พร้อม replay โดย **ไม่มีไฟล์เปลี่ยน**
- เทสต์กู้คืนปิดโปรเซสจริงด้วย `SIGKILL` แล้วตรวจและกู้คืนจากโปรเซสใหม่
- ตรวจแพ็กเกจและลิงก์จริง 60 จุด เก็บหลักฐานไว้เป็นส่วนตัว แล้วลบ workspace ทดสอบชั่วคราว

## สิ่งที่ไม่ผ่านในรอบแรก

1. หลังเพิ่มการตรวจวันหมดอายุ ผลกรองใหม่ทุกคำถามทำให้แคชของระบบค้นหาใช้ซ้ำไม่ได้ แก้โดยรักษาแคชและยกเลิกเมื่อข้อมูลหรือเวลาที่เกี่ยวข้องเปลี่ยน
2. รอบ native แรก Lead ทำการอัปเดตเองขณะที่ Curator รับเฉพาะงาน preference จึงไม่นับว่าผ่าน workflow ที่ตั้งใจไว้ รอบแก้ส่งงานอัปเดตครบชุดให้ Curator ตัวเดียว และผ่านจาก trace จริง
3. คู่มืออ้างถึงรายงานที่ไม่ได้อยู่ใน npm package จึงแก้การจัดแพ็กเกจและตรวจลิงก์ใหม่

ผลที่ล้มเหลวยังอยู่ในรายงาน โค้ดและชุดตรวจรวมเสร็จประมาณ 45 นาที แต่การทดสอบ native รอบแก้ การตรวจอิสระ และ cleanup ทำให้เวลารวมเกินเป้าหนึ่งชั่วโมง

## ก่อนทดลองกับ vault หลัก

อ่าน [คู่มือทดลองใช้](../guides/trial-mvp.md) แล้วใช้ guided setup เลือก host/model/vault จริง ควรเริ่มจากงานเล็กที่ตรวจผลได้ และใช้ Curator ผู้เขียนเพียงตัวเดียวต่อ vault
