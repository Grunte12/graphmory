## Failures found and changes made

1. **Catalog entry did not establish account support.** Codex rejected `gpt-6-luna` for this ChatGPT account. The installed role now uses the verified `gpt-5.6-luna`. Public installation guidance requires account-specific verification; it does not promise universal model availability.
2. **Legacy alias selected an incomplete installation.** The existing `mph` pointed to a copied OpenCode runtime missing embedding dependencies. The local alias now resolves to the normal global install, and the skill prefers canonical `graphmory`. Shared optional dependency resolution was verified for the copied launcher as well.
3. **The old OpenCode adapter denied necessary CLI access.** The template now declares a sub-agent and asks for Bash permission rather than categorically denying it. Local installation authorizes only Graphmory CLI calls and exact named Curator dispatch, preserving other parent restrictions.
4. **Host output truncation interrupted original-source reading.** `read-notes --pretty` emits multiline JSON with unchanged Markdown, paths and hashes. A regression assertion compares parsed output with the compact route. Curator guidance uses this option before inventing shell formatters.
5. **Model-generated preflight and argument mistakes.** Early OpenCode attempts used disallowed shell discovery/formatters or an invalid recall flag. Those failures were retained; the successful isolated test used the supported CLI and full original reads. They are not counted as successes or silently discarded.
6. **Normal plugin runtime exposed an additional restriction.** Successful isolated execution was followed by an ordinary plugin-enabled run. An existing custom capabilities plugin maintains a shell-agent allowlist that omitted `memory_curator`. Exact named parent dispatch was already allowed. The local fix adds only that role while retaining Graphmory command restrictions. A subsequent doctor-only child appended `echo` to the command and correctly encountered an approval request; permissions were not broadened. A final ordinary-runtime child used plain CLI commands and completed hybrid retrieval, original reads and a cited Brief. It recovered from an initial denied native skill-file read by using the host skill loader. All five synthetic notes remained unchanged.
7. **Motion proof had weak contrast and an exit overflow.** Orange headline text was replaced with dark text and orange emphasis; the exit translation was removed. The final proof passed the checks above.

## Installation boundaries

Both hosts use the same default vault and outside-vault checkpoint state. Neither changes state roots to evade pending writes. The local model/vector cache is separate from the Markdown vault. First semantic use downloads and initializes the model; warm retrieval is a different condition and was not timed here.

The CLI enforces its own content routes. It does not sandbox native host filesystem tools. Curator and lead instructions therefore retain the prepare-before-edit and receipt-before-APPLIED rules.

OpenCode's existing lead model was preserved. Space Bunny was used for the free smoke test; this does not establish that it is the best model. Its availability is temporary, and privacy terms should be rechecked before private memory use. See [OpenCode Zen documentation](https://opencode.ai/docs/en/zen/). For custom Codex roles, see [official sub-agent documentation](https://developers.openai.com/codex/subagents/).

System fonts are loaded locally rather than redistributed. See [media credits](../media/graphmory-motion/CREDITS.md).

Final publication checks include whitespace, local README asset links, full video decoding, and npm packaging. The previously passed runtime release gate remains the software acceptance evidence; this experiment does not claim broader MVP write/recovery certification or superiority over another tool.
