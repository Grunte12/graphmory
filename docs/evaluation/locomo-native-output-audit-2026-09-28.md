The initial progress message inferred an empty candidate pool from empty source reads; inspection corrected that inference before reporting the comparison.

The [post-outcome replay artifact](../../eval/reader-pilot/locomo-native-output-audit-2026-09-28.json) reran the exact native hybrid query and three pages on the same isolated immutable index for `conv-42:62`. It returned 10, 10 and 9 candidates. Every adapted page SHA-256 exactly matched the recorded live page hash. Thus all 29 indexed notes were delivered to the Curator across the three pages; zero source-read requests is a reader behavior, not a retrieval miss.

Native records contain both `content` and `matched_chunk` plus entity/metadata/score fields. Across the pages those two fields total 88,803 and 88,477 characters respectively; they are distinct fields and should not be blindly treated as unique information. Original Markdown totals 94,240 characters, while normalized indexed Markdown totals 96,136. These totals do not prove every source span was delivered, and normalization means raw whole-file identity is a different contract from a returned native content field.

The mediated fresh-session runner retains previous paths but does not redeliver older-page preview bodies unless an original is read. Losing earlier preview context is a plausible contributor requiring a separate controlled session test, not a proven explanation for this answer. This adapter/output audit is not a replacement answer trial, official score, semantic grounding result, or Basic Memory product-quality verdict. It ran while later answer trials were still active; no performance claim is based on its replay times. The complete comparison is in the [native reader report](locomo-native-reader-2026-09-28.md).
