# Trace-preserving native dispatch probe

Preregister one diagnostic attempt after the blocked lifecycle run. It is not a repetition scored as another lifecycle success: the child only runs installed `graphmory doctor --json` against the isolated package, without vault writes. Retain a native parent rollout by omitting `--ephemeral` so exact spawn arguments/response can be audited.

Use the same installed model choices (`gpt-5.6-sol` Lead, `gpt-5.6-luna` Curator, both low), trusted temporary project, and generated role. The official pinned V2 source supports `agent_type="graphmory_curator"`, `fork_turns="none"`, no `fork_context`. Require the Lead to inspect its exposed schema and stop if that shape is unavailable. Do not tune prompts, override the child model, or fall back to a generic child.

Success requires actual parent spawn arguments and response, one runtime child binding with the correct role/model, terminal child task, and an actual child doctor command returning valid. Missing any of these leaves dispatch unverified. Preserve failures and keep the earlier failed experiment unchanged. This does not verify lifecycle persistence, full memory workflow, answer quality or comparative latency/cost.

Capture metadata-only evidence/report; remove the isolated package/project after terminal execution. Archive exact completed test sessions through the app, without deleting unrelated or global rollout files. Official benchmarks, holdouts and private vault remain untouched.
