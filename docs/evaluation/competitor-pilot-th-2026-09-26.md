# ผลเปรียบเทียบคู่แข่งรอบแรก

ทดสอบจริงบนเครื่อง: Basic Memory 0.23.2 โหมด text search เทียบ Graphmory บน LongMemEval 14 คำถามเดียวกัน (12 มีคำตอบ อีก 2 ไม่มีคำตอบ)

| ระบบ — ใช้คำถามอย่างเดียว | หลักฐานครบใน 3 อันดับแรก | หลักฐานครบใน 12 อันดับแรก |
| --- | ---: | ---: |
| Basic Memory text | 8/12 | 12/12 |
| Graphmory BM25 | 10/12 | 12/12 |
| Graphmory fusion | 10/12 | 12/12 |

**แปลผล:** เราจัดหลักฐานขึ้นอันดับต้นได้ดีกว่าในตัวอย่างนี้ แต่ตัวอย่างยังเล็ก และไม่ได้ทดสอบ hybrid/semantic ของคู่แข่ง จึงยังพูดว่าชนะทั้งระบบไม่ได้ ไม่มีการเรียกโมเดลตอบคำถามหรือ judge ดังนั้นคะแนนนี้ไม่ใช่ความแม่นยำของคำตอบ

## สิ่งที่พบและสิ่งที่ปรับ

- คำถามที่ต่อท้ายด้วยวันที่ทำให้ Basic Memory ไม่คืนผลเลย การตรวจ index และ known-item test ช่วยจับว่าปัญหาอยู่ที่รูปแบบ query จึงทดลองคำถามอย่างเดียวกับทั้งสองระบบ และเก็บทั้งสองผลไว้
- Graphmory BM25 ดีขึ้นจาก 8/12 เป็น 10/12 บนชุดพัฒนา แต่บนชุดใหม่ได้ 11/12 เท่ากันทั้งสองรูปแบบ จึงยังไม่เปลี่ยน production เพื่อไล่คะแนน
- เพิ่มตัวเลือก eval เพื่อแยกข้อความค้นหาจากวันที่อ้างอิง และเลือกชุดทดสอบที่ตรึง IDs ได้ วันที่ยังต้องส่งให้ reader เมื่อวัดงาน temporal reasoning
- Basic Memory stdout ประมาณ 54 KB ต่อคำค้น (ค่ามัธยฐานรอบ question-only) เป็นจุดที่ควรทดลอง compact output ในอนาคต แต่ยังไม่ใช่หลักฐานเรื่องค่า token เพราะโครงสร้างผลลัพธ์ต่างกัน

## ควรทำต่ออะไร

1. เทียบ Basic Memory hybrid ตามค่าแนะนำก่อนสรุปความสามารถ semantic — รอบนี้ยังไม่ได้ดาวน์โหลดโมเดล
2. ใช้ reader/judge เดียวกันเพื่อวัดคำตอบถูกต้องและการไม่ตอบเมื่อข้อมูลไม่พอ
3. เพิ่มจำนวนคำถามและวัดต้นทุนต่อคำตอบที่ถูกต้อง ก่อนอ้างความเหนือกว่า

รอบนี้ไม่มีค่า API และไม่ใช้ vault ส่วนตัว ผลตรวจเดิม 238 tests ผ่าน; หลังเพิ่มตัวเลือก eval ชุดทดสอบที่เกี่ยวข้องผ่าน ไม่มีการเปลี่ยนอัลกอริทึม production Luna ช่วยวิจัย/ติดตั้ง แต่ถูก usage limit ก่อนจบ จึงให้ lead รันส่วน deterministic และ audit ต่อ รอบนี้ทำครบเพียงหนึ่งคู่แข่งเพื่อจำกัดการใช้โควตา
